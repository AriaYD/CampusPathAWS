我们做什么

一个学生校园成长规划操作系统，不是又一个活动聚合网站

你设一个主目标和一个候选目标，系统从最新的几十份真实岗位数据里拆解出要什么能力，再从全校海量资源里挑出补得上缺口的活动、课程和机会，排进你真实有空的时段。

产出的是一条带版本、带依据、随变化滚动更新的路径，不是一份聊完就关掉的建议清单。

CampusPath 不替代导师、Career Center、学院顾问或 LMS——它是学校资源、外部机会与学生个人发展之间的发现、匹配与编排层。

对学生

把长期方向倒推成当下可执行、且不挤压生活的路径；每条建议都说明补什么差距、形成什么证据、为什么是现在。

对学校

把已经投入巨大成本、触达效率却很低的资源，变成可测量、可改进、可归因的成长资产；并第一次看到「资源池覆盖不了学生的哪些真实需求」。

「学校资源」的口径

凡是因为学生的在校身份而能拿到的机会，都算学校资源——校友内推、企业来校招聘、合作方名额、跨校联盟活动。所以我们不分校内校外，只分：是否发现、是否够格、是否用上。

痛点

学生不是缺资源，而是难以把海量资源转化成自己的成长路径

一所大学里，每个学院有自己的活动，几百个社团各办各的，还有协会、实验室、研究中心、校企合作。这些机会散落在不同部门的官网上——每个官网的架构还都不一样。你得先找到真正的活动页，然后经常回去看，才不会错过。

对一个课业本来就很重的学生来说，这基本做不到，除非你自己搭一套全量采集系统。而且即使看到了，也常常撞上自己的时间，或者报完才发现根本不是自己想要的。

你能得到什么

六件在别处拿不到的事

四态资格，不是「能 / 不能」

大一学生看到只限大三的实习，不会被静默过滤掉，而是标为「未来可申请」，并告诉你这一年该补什么。四态：现在合格 / 未来可达 / 信息不足 / 本轮不适用。

每条建议都说得出为什么

补什么差距、形成什么证据、为什么是现在。拆解出来的每一条都能点开溯源到岗位原文，不是模型编的。

个性化之外仍可自主发现

资讯广场展示校方全部审核通过的资源，可见性不由 AI 排序决定。任一条目都能点「为什么没推荐我」，给出规则引擎签发的凭据式解释。

先看真实容量，再安排任务

日历默认只读忙闲，不读事件标题。规划前先算课程、已有安排、睡眠与三餐保护块、可支配时间和缓冲，只在你真的有空的格子里排。

从推荐走到行动的闭环

材料、日历、提醒、状态和替代方案连成一条；活动做完写反思，自动沉淀为成长证据。

不会一味 push 你

睡眠被挤压且负荷持续偏高时，系统会预警而不是继续往日历里塞东西。这条安全护栏链路零大模型——判定归阈值，文案归固定模板。

越用越懂你

它记住的不是你点了什么，是你为什么改主意

学生从入学到毕业会连续用四年甚至更久。系统必须记住：已修课程与项目、你明确拒绝过的方向和原因、哪些活动对你高价值哪些低价值、你做过的目标变更和取舍、你的节奏与精力偏好，以及哪些技能你已经拿到了、不该再重复安排。

层存什么更新规则
L0 当前档案学业、经历、成果、技能、目标、偏好、容量与约束的当前有效状态只由权威来源或学生确认更新，每次变更留档案变更事件
L1 事件时间线参加、申请、完成、放弃、反馈、计划版本等事件只追加；错了用更正事件处理，不改历史
L2 语义记忆从经历里提炼的兴趣、模式与上下文带来源、时间、置信度与过期策略
L3 证据与笔记你的原始笔记、作品、证书、反思原文与附件你拥有；默认不向校方共享

记忆的安全规矩

区分「学生原话」「系统推断」「外部事实」，不把推断伪装成事实；新旧冲突时保留时间线、用 supersedes 表示更新，不静默覆盖；不把短期情绪写成永久性格标签。

你随时可以反悔

任何一条记忆都能搜索、纠正、锁定、删除、导出、暂停。读取时只召回与当前任务相关的最小上下文。

反思三轨分开建模

你发生了什么变化 / 你想长期保留什么 / 活动本身是否兑现宣传——这是三件事。混在一起，学校就永远收不到有用的信号。

倒逼学生真的去总结

反思必须先绑定一个具体对象才能创建，防止泛泛而谈。预约顾问的会面还有一层：写完并保存这次会面的反思，才能看到顾问给你的关键建议。

关键设计：个人不适配与全局低质是分开的。「太基础」「太难」走个人契合标签，只调整你自己的推荐难度，不惩罚这个活动；「宣传夸大、内容空泛」达到样本阈值后才降低该届次的置信度并进入复核。

怎么用

一条真的闭合的环，学生端与校方端互为对方的输入

  1. 01

    开通与授权

    接入学校教务系统；授权个人日历（默认只读忙闲，不读事件正文）。系统这才知道你的在校学业课程状态、真实有多少时间。

  2. 02

    建立成长档案

    上传简历，系统确定性解析后直接整理进「我的成长档案」总览，并弹窗逐条列出新增内容供你自行核对，任何一条都能当场撤销。国际生可在这里勾选「我是国际生」，一个版本化的 Context Pack 会注入后续所有环节。

  3. 03

    目标工作室

    设一个主目标 + 一个候选目标，设定两者的推进配比，点「开始规划」。后台三段式跑：采集真实岗位数据 → 分析比对 → 目标拆解。拆解结果分三层：

    • 软实力——口才、领导力、影响力、团队协作；
    • 硬实力——绩点与核心课绩点要求；
    • 个人真实硬件实力——比赛与奖项、项目与论文、实习经历、证书与软件。

    每一条都能点开看它来自哪份岗位描述。系统同时给出两个目标的共享缺口与分叉点——共享的先做，两条路都不亏。

  4. 04

    发现

    • 资讯广场：全校、各学院、社团、协会、实验室、教授、校企的机会都在这里，按十大主办方类别与主题、年级、资格、线上线下、截止时间等标签筛。已过期的归入独立分组并明确标注，不会混在「现在可以报名」里，也不会被推荐给你。
    • 为你推荐：基于你的档案 + 目标拆解 + 记忆里的偏好挑出来的，每张卡写明为什么推荐你。四态资格在卡片上直接可见。
  5. 05

    规划与批准

    报名的活动进入行动中心。系统按未来两周 / 一个月 / 一学期 / 一学年四档跨度铺开，并自动倒排提前量——大型比赛提前一两周到一个月准备、等级证书提前一两个月、语言类考试提前一年，就出现在对应跨度的日程里。规划完先弹窗给你审批，说明依据（你的目标、你的档案、记忆里的偏好），你批准了才写进日历。日历是周/月网格且本身就是编辑器：随时改时间、加睡眠与三餐保护块、加缓冲。改完是否重排，也问你。

    • 你还可以按照个人的精力水平和时间空闲程度，自行设置规划安排的三档不同强度：轻负荷、均衡、进取。
    • 行动中心里还有选修课推荐：必修按培养方案载入不做推荐，选修按你的档案、目标与所需技能推荐，附课程全名、简介、先修原文与教务系统跳转链接。
  6. 06

    护栏（安全护栏零大模型）

    睡眠只看你自己声明的睡眠窗口和日历里占用它的安排——没声明就不推断，如实显示「数据覆盖 0 天」。绝不从「日历上有空档」反推你在睡觉或在运动。判定是一个纯计数模型（下列为实现中的实测阈值）：过劳日 = 有效睡眠不足 7 小时且当天学习工作超过 11 小时；滚动 14 天内合格日 ≥ 10 天 → 第一层预警；滚动 28 天内合格日 ≥ 20 天 → 第二层要求填两份量表。

    • 两份量表是 ISI（失眠严重程度）与 PSS-10（压力自评），用来区分「熬夜是个人习惯」还是「学业压力造成的」——这个区分很重要，两者该给的支持完全不同。
    • 轻度 → 提示可联系你自己填写的辅导员；中度失眠或压力值偏高 → 引导预约心理咨询室时段。
    • 最上面还有第三层：紧急求助按钮，跳过全部排队直连学校心理咨询专员（如有无端恶意占用，每学期 2 次，第 3 次停用一学期——但停用的响应里仍然附上热线）。

    提醒最多两次，只对学生可见，默认不进任何校方后台；非紧急的校方触达必须有你预先同意或当次主动请求。

  7. 07

    反思与沉淀

    活动结束后写反思与四维评分。写完，活动自动归档为成长证据进入「成长动态跟踪」，挂在对应的能力细则下。这一步同时产生北极星指标 VGA（Verified Growth Actions）——它不奖励点击、收藏、报名或忙碌本身，只数真正做成并留下证据的行动。

  8. 08

    回到学校（闭环的另一半）

    • Career Center 管理端统一注册并监控所有信息源，看得到每个源的健康度，每天定时抓一次，也可以一键实时抓；
    • 社团负责人、实验室、教授通过投稿台提交活动 → 进入审核队列 → 批准后才进资讯广场；
    • 批准的活动自带二维码下发给主办方，活动开始时激活，到场的人扫码签到；
    • 于是学校拿到几组真实数据：谁真的来了（签到）和他们怎么评价（匿名四维评分）等等；
    • 由此看清：哪类活动更受欢迎、哪些活动质量高、真实好评率多少、哪些领域有缺口、哪些专业的资源不够；
    • 报告按周 / 月 / 学期 / 学年自动生成，也可以随时手动生成一份；
    • 活动结束两个月统计冻结、自动下架并归档。

闭环合上了：学生从海量资源里精准找到匹配自己目标的活动 → 参加 → 写反思 → 沉淀成证据推动下一轮规划；而这些反馈同时回到学校，让学校及时看到学生的真实需求与趋势变化，据此补缺口、给高质量活动倾斜资源。互利，双向推动。

技术架构

双平面 + 契约先行：类型不允许的数据，物理上流不过去

语义平面：6 个语义 Agent（编排 / 学生上下文 / 学业 / 目标缺口 / 机会抽取 / 路径规划）——唯一允许调模型的那一层。

确定性平面：9 个零大模型的服务（规则与约束、容量与日历、Wellbeing 文案生成、状态与记忆、行动与同意、匿名聚合、事件监控与重规划、发布审核审计、连接器与目录）。判定、阈值、资格、容量全在这一侧，可复现、可审计。

两个平面之间的每一次数据交换都由数据契约类型定形。

#六条架构红线：每条都有对应的自动化测试，测试不过构建就失败
1路径规划 Agent 是唯一做取舍的 Agent；其余只出事实与候选，输出类型里根本没有排序字段
2Wellbeing 安全护栏判断零大模型——判定归阈值，文案归固定模板；构建期禁止 import 模型 SDK
3日历凭据不进任何模型上下文——止步于容量服务，由类型层强制
4机会抽取 Agent 的工具白名单只有两个；外部内容作为数据块传入，永不拼进 system prompt
5每个计划条目必带规则引擎签发的校验凭据，缺失即被 API 拒绝
6私人反思原文到校方聚合的路径在类型层不存在——不是「我们不传」，是传不过去

运行在哪里

模型只有一个出口：Amazon Bedrock · Nova Pro via Strands Agents SDK（区域内 `amazon.nova-pro-v1:0`，2026-09 起默认后端）；六个语义 Agent 统一经由 Strands Agents SDK（`Agent` + 工具白名单 hook + 提示词卫生 hook）调用模型，部署跑在 Bedrock AgentCore Runtime 上；Vertex Gemini 3.5（代际下限在构造时检查）保留作为可切换的备选后端；Cloud Run 跑学生 App、API 与每日巡检的 Cloud Run Job（Cloud Scheduler 触发）；全部可变状态检查点到 Firestore、冷启动回读；每次模型调用、工具调用、修复循环都是一条 OpenTelemetry span 进 Cloud Trace；Moodle 沙箱通过自研只读 MCP 接入；密钥在 Secret Manager。

模型可以换（架构承诺）

全系统的模型出口收敛在一个适配点上，Agent 层依赖的是一个只有单个方法的抽象接口。换型号是部署配置，不改一行代码；换供应商（校方自有模型、其他云厂商、本地私有部署）只需为这个接口提供一个实现——6 个 Agent、9 个确定性服务、全部数据契约类型与红线测试零改动。

确定性平面不受影响

资格判定、容量计算、健康阈值、隐私抑制这些最需要稳定与可审计的部分本来就不调模型，不受任何模型更换影响。产品价值不依赖某一个特定模型——学校要用什么模型，是学校的决定。

我們做什麼

一個學生校園成長規劃操作系統，不是又一個活動聚合網站

你設一個主目標和一個候選目標，系統從最新的幾十份真實崗位數據裏拆解出要什麼能力，再從全校海量資源裏挑出補得上缺口的活動、課程和機會，排進你真實有空的時段。

產出的是一條帶版本、帶依據、隨變化滾動更新的路徑，不是一份聊完就關掉的建議清單。

CampusPath 不替代導師、Career Center、學院顧問或 LMS——它是學校資源、外部機會與學生個人發展之間的發現、匹配與編排層。

對學生

把長期方向倒推成當下可執行、且不擠壓生活的路徑；每條建議都説明補什麼差距、形成什麼證據、為什麼是現在。

對學校

把已經投入巨大成本、觸達效率卻很低的資源，變成可測量、可改進、可歸因的成長資產；並第一次看到「資源池覆蓋不了學生的哪些真實需求」。

「學校資源」的口徑

凡是因為學生的在校身份而能拿到的機會，都算學校資源——校友內推、企業來校招聘、合作方名額、跨校聯盟活動。所以我們不分校內校外，只分：是否發現、是否夠格、是否用上。

痛點

學生不是缺資源，而是難以把海量資源轉化成自己的成長路徑

一所大學裏，每個學院有自己的活動，幾百個社團各辦各的，還有協會、實驗室、研究中心、校企合作。這些機會散落在不同部門的官網上——每個官網的架構還都不一樣。你得先找到真正的活動頁，然後經常回去看，才不會錯過。

對一個課業本來就很重的學生來説，這基本做不到，除非你自己搭一套全量採集系統。而且即使看到了，也常常撞上自己的時間，或者報完才發現根本不是自己想要的。

六件在別處拿不到的事

四態資格，不是「能 / 不能」

大一學生看到只限大三的實習，不會被靜默過濾掉，而是標為「未來可申請」，並告訴你這一年該補什麼。四態：現在合格 / 未來可達 / 信息不足 / 本輪不適用。

每條建議都説得出為什麼

補什麼差距、形成什麼證據、為什麼是現在。拆解出來的每一條都能點開溯源到崗位原文，不是模型編的。

個性化之外仍可自主發現

資訊廣場展示校方全部審核通過的資源，可見性不由 AI 排序決定。任一條目都能點「為什麼沒推薦我」，給出規則引擎簽發的憑據式解釋。

先看真實容量，再安排任務

日曆默認只讀忙閒，不讀事件標題。規劃前先算課程、已有安排、睡眠與三餐保護塊、可支配時間和緩衝，只在你真的有空的格子裏排。

從推薦走到行動的閉環

材料、日曆、提醒、狀態和替代方案連成一條；活動做完寫反思，自動沉澱為成長證據。

不會一味 push 你

睡眠被擠壓且負荷持續偏高時，系統會預警而不是繼續往日曆裏塞東西。這條安全護欄鏈路零大模型——判定歸閾值，文案歸固定模板。

越用越懂你

它記住的不是你點了什麼，是你為什麼改主意

學生從入學到畢業會連續用四年甚至更久。系統必須記住：已修課程與項目、你明確拒絕過的方向和原因、哪些活動對你高價值哪些低價值、你做過的目標變更和取捨、你的節奏與精力偏好，以及哪些技能你已經拿到了、不該再重複安排。

層存什麼更新規則
L0 當前檔案學業、經歷、成果、技能、目標、偏好、容量與約束的當前有效狀態只由權威來源或學生確認更新，每次變更留檔案變更事件
L1 事件時間線參加、申請、完成、放棄、反饋、計劃版本等事件只追加；錯了用更正事件處理，不改歷史
L2 語義記憶從經歷裏提煉的興趣、模式與上下文帶來源、時間、置信度與過期策略

記憶的安全規矩

區分「學生原話」「系統推斷」「外部事實」，不把推斷偽裝成事實；新舊衝突時保留時間線、用 supersedes 表示更新，不靜默覆蓋；不把短期情緒寫成永久性格標籤。

你隨時可以反悔

任何一條記憶都能搜索、糾正、鎖定、刪除、導出、暫停。讀取時只召回與當前任務相關的最小上下文。

反思三軌分開建模

你發生了什麼變化 / 你想長期保留什麼 / 活動本身是否兑現宣傳——這是三件事。混在一起，學校就永遠收不到有用的信號。

倒逼學生真的去總結

反思必須先綁定一個具體對象才能創建，防止泛泛而談。預約顧問的會面還有一層：寫完並保存這次會面的反思，才能看到顧問給你的關鍵建議。

關鍵設計：個人不適配與全局低質是分開的。「太基礎」「太難」走個人契合標籤，只調整你自己的推薦難度，不懲罰這個活動；「宣傳誇大、內容空泛」達到樣本閾值後才降低該屆次的置信度並進入複核。

怎麼用

一條真的閉合的環，學生端與校方端互為對方的輸入

  1. 01

    開通與授權

    接入學校教務系統；授權個人日曆（默認只讀忙閒，不讀事件正文）。系統這才知道你的在校學業課程狀態、真實有多少時間。

  2. 02

    建立成長檔案

    上傳簡歷，系統確定性解析後直接整理進「我的成長檔案」總覽，並彈窗逐條列出新增內容供你自行核對，任何一條都能當場撤銷。國際生可在這裏勾選「我是國際生」，一個版本化的 Context Pack 會注入後續所有環節。

  3. 03

    目標工作室

    設一個主目標 + 一個候選目標，設定兩者的推進配比，點「開始規劃」。後台三段式跑：採集真實崗位數據 → 分析比對 → 目標拆解。拆解結果分三層：

    • 軟實力——口才、領導力、影響力、團隊協作；
    • 硬實力——績點與核心課績點要求；
    • 個人真實硬件實力——比賽與獎項、項目與論文、實習經歷、證書與軟件。

    每一條都能點開看它來自哪份崗位描述。系統同時給出兩個目標的共享缺口與分叉點——共享的先做，兩條路都不虧。

  4. 04

    發現

    • 資訊廣場：全校、各學院、社團、協會、實驗室、教授、校企的機會都在這裏，按十大主辦方類別與主題、年級、資格、線上線下、截止時間等標籤篩。已過期的歸入獨立分組並明確標註，不會混在「現在可以報名」裏，也不會被推薦給你。
    • 為你推薦：基於你的檔案 + 目標拆解 + 記憶裏的偏好挑出來的，每張卡寫明為什麼推薦你。四態資格在卡片上直接可見。
  5. 05

    規劃與批准

    報名的活動進入行動中心。系統按未來兩週 / 一個月 / 一學期 / 一學年四檔跨度鋪開，並自動倒排提前量——大型比賽提前一兩週到一個月準備、等級證書提前一兩個月、語言類考試提前一年，就出現在對應跨度的日程裏。規劃完先彈窗給你審批，説明依據（你的目標、你的檔案、記憶裏的偏好），你批准了才寫進日曆。日曆是周/月網格且本身就是編輯器：隨時改時間、加睡眠與三餐保護塊、加緩衝。改完是否重排，也問你。

    • 你還可以按照個人的精力水平和時間空閒程度，自行設置規劃安排的三檔不同強度：輕負荷、均衡、進取。
    • 行動中心裏還有選修課推薦：必修按培養方案載入不做推薦，選修按你的檔案、目標與所需技能推薦，附課程全名、簡介、先修原文與教務系統跳轉鏈接。
  6. 06

    護欄（安全護欄零大模型）

    睡眠只看你自己聲明的睡眠窗口和日曆裏佔用它的安排——沒聲明就不推斷，如實顯示「數據覆蓋 0 天」。絕不從「日曆上有空檔」反推你在睡覺或在運動。判定是一個純計數模型（下列為實現中的實測閾值）：過勞日 = 有效睡眠不足 7 小時且當天學習工作超過 11 小時；滾動 14 天內合格日 ≥ 10 天 → 第一層預警；滾動 28 天內合格日 ≥ 20 天 → 第二層要求填兩份量表。

    • 兩份量表是 ISI（失眠嚴重程度）與 PSS-10（壓力自評），用來區分「熬夜是個人習慣」還是「學業壓力造成的」——這個區分很重要，兩者該給的支持完全不同。
    • 輕度 → 提示可聯繫你自己填寫的輔導員；中度失眠或壓力值偏高 → 引導預約心理諮詢室時段。
    • 最上面還有第三層：緊急求助按鈕，跳過全部排隊直連學校心理諮詢專員（如有無端惡意佔用，每學期 2 次，第 3 次停用一學期——但停用的響應裏仍然附上熱線）。

    提醒最多兩次，只對學生可見，默認不進任何校方後台；非緊急的校方觸達必須有你預先同意或當次主動請求。

  7. 07

    反思與沉澱

    活動結束後寫反思與四維評分。寫完，活動自動歸檔為成長證據進入「成長動態跟蹤」，掛在對應的能力細則下。這一步同時產生北極星指標 VGA（Verified Growth Actions）——它不獎勵點擊、收藏、報名或忙碌本身，只數真正做成並留下證據的行動。

  8. 08

    回到學校（閉環的另一半）

    • Career Center 管理端統一註冊並監控所有信息源，看得到每個源的健康度，每天定時抓一次，也可以一鍵實時抓；
    • 社團負責人、實驗室、教授通過投稿台提交活動 → 進入審核隊列 → 批准後才進資訊廣場；
    • 批准的活動自帶二維碼下發給主辦方，活動開始時激活，到場的人掃碼簽到；
    • 於是學校拿到幾組真實數據：誰真的來了（簽到）和他們怎麼評價（匿名四維評分）等等；
    • 由此看清：哪類活動更受歡迎、哪些活動質量高、真實好評率多少、哪些領域有缺口、哪些專業的資源不夠；
    • 報告按周 / 月 / 學期 / 學年自動生成，也可以隨時手動生成一份；
    • 活動結束兩個月統計凍結、自動下架並歸檔。

閉環合上了：學生從海量資源裏精準找到匹配自己目標的活動 → 參加 → 寫反思 → 沉澱成證據推動下一輪規劃；而這些反饋同時回到學校，讓學校及時看到學生的真實需求與趨勢變化，據此補缺口、給高質量活動傾斜資源。互利，雙向推動。

技術架構

雙平面 + 契約先行：類型不允許的數據，物理上流不過去

語義平面：6 個語義 Agent（編排 / 學生上下文 / 學業 / 目標缺口 / 機會抽取 / 路徑規劃）——唯一允許調模型的那一層。

確定性平面：9 個零大模型的服務（規則與約束、容量與日曆、Wellbeing 文案生成、狀態與記憶、行動與同意、匿名聚合、事件監控與重規劃、發佈審核審計、連接器與目錄）。判定、閾值、資格、容量全在這一側，可復現、可審計。

兩個平面之間的每一次數據交換都由數據契約類型定形。

#六條架構紅線：每條都有對應的自動化測試，測試不過構建就失敗

5每個計劃條目必帶規則引擎簽發的校驗憑據，缺失即被 API 拒絕
6私人反思原文到校方聚合的路徑在類型層不存在——不是「我們不傳」，是傳不過去

運行在哪裏

模型只有一個出口：Amazon Bedrock · Nova Pro via Strands Agents SDK（區域內 `amazon.nova-pro-v1:0`，2026-09 起默認後端）；六個語義 Agent 統一經由 Strands Agents SDK（`Agent` + 工具白名單 hook + 提示詞衞生 hook）調用模型，部署跑在 Bedrock AgentCore Runtime 上；Vertex Gemini 3.5（代際下限在構造時檢查）保留作為可切換的備選後端；Cloud Run 跑學生 App、API 與每日巡檢的 Cloud Run Job（Cloud Scheduler 觸發）；全部可變狀態檢查點到 Firestore、冷啓動回讀；每次模型調用、工具調用、修復循環都是一條 OpenTelemetry span 進 Cloud Trace；Moodle 沙箱通過自研只讀 MCP 接入；密鑰在 Secret Manager。

模型可以換（架構承諾）

全系統的模型出口收斂在一個適配點上，Agent 層依賴的是一個只有單個方法的抽象接口。換型號是部署配置，不改一行代碼；換供應商（校方自有模型、其他雲廠商、本地私有部署）只需為這個接口提供一個實現——6 個 Agent、9 個確定性服務、全部數據契約類型與紅線測試零改動。

確定性平面不受影響

資格判定、容量計算、健康閾值、隱私抑制這些最需要穩定與可審計的部分本來就不調模型，不受任何模型更換影響。產品價值不依賴某一個特定模型——學校要用什麼模型，是學校的決定。

誰説了算

系統給排序，你來拍板

學生自主

你可以拒絕、修改、暫停、鎖定任何一條路徑；寫日曆、發消息、申請機會都需要你明確批准；探索型學生不會被逼着提前確定唯一職業目標。

檔案由你確認

證書、LMS 記錄和 Agent 反思可以提出檔案更新建議，但不能無提示地改寫你的檔案；「學生自報」「系統觀察」「來源驗證」始終分開標註。

證據優先於模型自信

資格、截止日期、項目要求必須指向來源；不確定時顯示「需要確認」，而不是編一個答案。

校方只看聚合，不能下鑽到人

任何視圖的樣本量低於閾值一律顯示 Insufficient evidence 並抑制該格，不顯示看似精確的數字；界面上沒有「查看構成這個數字的學生」的入口，後端也不提供這種查詢。

這個產品不是什麼：不是保證進入某家公司或學校的成功預測器；不是替學生做不可逆人生決定的自動決策系統；不是用活動數量或簡歷長度衡量成長的系統；不是醫療器械、心理診斷工具或自殺風險預測系統；不是僅憑日曆空檔就向學校報告學生的監控工具。

What we do

A growth-planning operating system for students — not another events aggregator

You set one primary goal and one candidate goal. The system reads dozens of live job postings, works backwards to the capabilities they demand, then picks the activities, courses and opportunities across campus that close those gaps — and schedules them into hours you actually have.

What comes out is a versioned, sourced path that keeps updating as you change. Not a list of suggestions you close and forget.

CampusPath does not replace mentors, the Career Center, faculty advisors or the LMS. It is the discovery, matching and orchestration layer between campus resources, outside opportunities and a student's own development.

For students

A long-range direction turned into steps you can take now without crowding out your life. Every suggestion states which gap it closes, what evidence it produces, and why now.

For the university

Resources that cost a great deal and reach very few become measurable, improvable and attributable growth assets — and, for the first time, you can see which real student needs your resource pool does not cover.

What counts as a campus resource

Anything a student can reach because of their enrolment: alumni referrals, employers recruiting on campus, partner quotas, inter-university events. So we don't split on-campus from off-campus — only on discovered, eligible, and used.

Pain points

Students aren't short of resources — they're short of a way to turn them into a path

Every school runs its own events. Hundreds of societies run theirs. So do associations, labs, research centres and corporate partners. All of it sits on different departmental websites, each with its own structure. You have to find the real listing page, then keep going back so you don't miss anything.

For a student already carrying a full course load, that is not realistic — not unless you build yourself a scraper. And even when you do see something, it often collides with your schedule, or turns out to be the wrong thing only after you've signed up.

It learns you

What it remembers isn't what you clicked — it's why you changed your mind

A student uses this for four years or more. So the system has to remember completed courses and projects, the directions you explicitly turned down and why, which activities were worth your time and which weren't, the goal changes and trade-offs you made, your rhythm and energy preferences, and which skills you already have and shouldn't be scheduled for again.

The rules memory follows

Student's own words, system inference and external fact stay distinguishable — inference is never dressed up as fact. When old and new conflict, the timeline is preserved and the update supersedes rather than silently overwrites. A passing mood never becomes a permanent trait.

You can always take it back

Any memory can be searched, corrected, locked, deleted, exported or paused. Recall pulls the minimum context the current task needs — never your whole history.

Reflection has three separate tracks

What changed in you, what you want to keep long term, and whether the event delivered what it promised are three different things. Mixed together, the school never receives a usable signal.

It makes students actually reflect

A reflection has to be bound to a specific object before it can exist, which rules out saying nothing at length. Advisor meetings add one more turn: write and save your reflection first, and only then do you see what the advisor wrote for you.

A deliberate split: personal mismatch and genuine low quality are separate. "Too basic" and "too hard" become a personal fit tag that adjusts your own difficulty and does not penalise the event. "Overstated, thin content" only lowers that occurrence's confidence once it clears a sample threshold, and then it goes to review.

How it works

A loop that actually closes — each side is the other's input

  1. 01

    Connect and consent

    Link the student information system; authorise your calendar (busy/free only by default, never event bodies). Only then does the system know what you are enrolled in and how much time you actually have.

  2. 02

    Build your profile

    Upload a résumé; deterministic parsing files it straight into your profile overview, then a drawer lists every added line so you can check it — and undo any of them on the spot. International students can tick that status here, and a versioned Context Pack flows into everything downstream.

  3. 03

    Goal studio

    Set a primary goal, a candidate goal and the split between them, then press Start planning. Three stages run in the background: gather live job postings → compare → decompose. The breakdown has three tiers:

    • Soft skills — communication, leadership, influence, teamwork;
    • Hard academics — GPA and the GPA required in core courses;
    • Demonstrable assets — competitions and awards, projects and papers, internships, certificates and tooling.

    Every line opens to the job posting it came from. You also get the shared gaps and the fork points between your two goals — do the shared work first, and neither path loses.

  4. 04

    Discover

    • Information plaza: everything from the university, its schools, societies, associations, labs, professors and corporate partners sits here, filtered by ten organiser categories plus theme, year, eligibility, format and deadline. Expired listings move into their own group, clearly marked — they never sit among things you can still sign up for, and they are never recommended.
    • For You: drawn from your profile + goal breakdown + the preferences in your memory, and every card states why it was recommended to you. The four eligibility states are visible on the card.
  5. 05

    Plan, then approve

    Anything you sign up for lands in the action centre. Four ranges — next two weeks, a month, a term, a year — with lead times worked backwards automatically: a week to a month for major competitions, one to two months for certifications, a year for language exams, each appearing in the range it belongs to. The draft comes to you in a dialog first, stating what it was built on (your goals, your profile, the preferences in your memory), and only lands on your calendar once you approve. The calendar is a week/month grid and is itself the editor: move things, add sleep and meal protection blocks, add buffers. Whether an edit triggers a re-plan is also your call.

    • You can also set the planning intensity yourself — light, balanced or ambitious — according to your energy and how much free time you have.
    • The action centre also recommends electives: required courses are loaded from the programme plan and never recommended, while electives are matched to your profile, goals and the skills you need — with the full course title, description, the original prerequisite text and a link into the registry.
  6. 06

    Guardrails, with no language model

    Sleep is read only from the window you declared and whatever occupies it — nothing is inferred when you haven't declared, and it says "0 days covered" rather than guessing. An empty calendar slot is never taken as evidence that you slept or exercised. The judgement is pure counting (these are the thresholds in the build): an overloaded day means under 7 hours of effective sleep and over 11 hours of study or work; 10 such days in a rolling 14 raise the first-tier warning, 20 in a rolling 28 ask you to complete two scales.

    • The two scales are the ISI (insomnia severity) and PSS-10 (perceived stress), which separate "late nights are a habit" from "this is academic pressure" — the distinction matters, because the support each needs is completely different.
    • Mild → you are pointed at the counsellor you named yourself; moderate insomnia or high stress → you are guided to book a counselling slot.
    • Above all of that sits a third tier: an emergency button that skips every queue and reaches the counselling service directly (against groundless misuse: twice a term, and a third use suspends it for a term — though the suspension notice still carries the hotline).

    At most two reminders, visible only to the student, and by default they reach no institutional console; any non-urgent outreach from the university needs your prior consent or your own request.

  7. 07

    Reflect and accumulate

    Write a reflection and rate four dimensions. Once written, the activity files itself as growth evidence into your growth tracker, attached to the specific capability it evidences. This is also where the north-star metric VGA (Verified Growth Actions) comes from — it rewards neither clicks nor saves nor sign-ups nor busyness, only things actually completed with evidence left behind.

  8. 08

    Back to the university (the other half of the loop)

    • The Career Center console registers and monitors every source, with health per source, a scheduled daily crawl and a one-click live refresh;
    • Society leads, labs and professors submit through the publisher desk → the review queue → and only then does it reach the plaza;
    • An approved listing carries its own QR code, handed to the organiser and activated when the event starts; attendees scan to check in;
    • So the university gets real data: who actually turned up (check-in) and how they rated it (anonymous four-dimension scores), among others;
    • From which: which kinds of activity draw people, which are high quality, the real favourable rate, where the gaps are and which programmes are under-resourced;
    • Reports generate weekly / monthly / per term / per year, and can be generated on demand;
    • Two months after an event its statistics freeze, and it is delisted and archived.

The loop closes: a student finds, among thousands of listings, the ones that match their goal → takes part → reflects → and that becomes evidence driving the next round of planning; the same feedback returns to the university, showing real demand and how it is shifting, so gaps get filled and good activities get more resource. Both sides gain, and each pushes the other.

Under the hood

Two planes, contracts first: data the types forbid physically cannot flow

The semantic plane: six agents (orchestration, student context, academics, goal gaps, opportunity extraction, path planning) — the only layer permitted to call a model.

The deterministic plane: nine services with no language model anywhere (rules and constraints, capacity and calendar, wellbeing copy, state and memory, actions and consent, anonymous aggregation, monitoring and re-planning, publishing review and audit, connectors and catalog). Every judgement, threshold, eligibility decision and capacity calculation lives here — reproducible and auditable.

Every exchange between the two planes is shaped by a data contract type.

Where it runs

One model exit: Amazon Bedrock · Nova Pro via the Strands Agents SDK (in-region `amazon.nova-pro-v1:0`, the default backend since Sep 2026). All six semantic agents call the model through the Strands Agents SDK (an `Agent` plus a tool-whitelist hook and a prompt-hygiene hook), deployed on Bedrock AgentCore Runtime; Vertex Gemini 3.5 (generation floor asserted at construction) remains as a switchable alternate backend; Cloud Run serves the student app, the API and the daily source-sweep Job (triggered by Cloud Scheduler); all mutable state is checkpointed to Firestore and restored on cold start; every model call, tool call and repair round is an OpenTelemetry span in Cloud Trace; the Moodle sandbox connects through a read-only MCP we built; secrets live in Secret Manager.

The model is replaceable (an architectural commitment)

Every model call in the system converges on a single adapter, and the agent layer depends on an abstract interface with one method. Changing model version is deployment config, not code. Changing vendor — the university's own model, another cloud, an on-premise deployment — means writing one implementation of that interface, with zero changes to the six agents, the nine deterministic services, the contract types or the red-line tests.

The deterministic plane doesn't move

Eligibility, capacity, health thresholds and privacy suppression — the parts that most need to be stable and auditable — never call a model in the first place, so no model change touches them. The product's value doesn't rest on any one model. Which model to run is the university's decision.

You're in charge

The system ranks; you decide

Student autonomy

You can reject, edit, pause or lock any path. Writing to your calendar, sending a message or applying to something all need your explicit approval. Students who are still exploring are never pushed to commit to a single career goal early.

Your profile, your confirmation

Certificates, LMS records and agent reflections can propose profile updates, but cannot rewrite your profile without telling you. Self-reported, system-observed and source-verified stay labelled apart.

Evidence outranks model confidence

Eligibility, deadlines and programme requirements must point at a source. When it's uncertain, the answer is "needs confirmation", not an invented one.

The school sees aggregates and cannot drill down

Any cell below the sample threshold shows Insufficient evidence and is suppressed — never a number that looks precise. There is no interface for "show me the students behind this figure", and the backend offers no such query.

What this product is not: a success predictor guaranteeing entry anywhere; an automated decision system making irreversible life choices for a student; a system measuring growth by activity count or résumé length; a medical device, psychological diagnostic or suicide-risk predictor; or a monitoring tool that reports on students from calendar gaps alone.

We don't claim what we have no baseline for

Nothing here claims improved employment or academic outcomes — there is no real baseline to claim it against. Every target above is a pilot hypothesis.

Judgement metrics must produce byte-identical results across two runs, and the gold labels are implemented separately from the engine on purpose — generating labels with the same code you evaluate with is marking your own homework.
